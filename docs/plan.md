1つの段階が終わるごとに動く状態で止まり、次に進みます。
APIキーがなくても段階4までは進められます。

## 段階0 土台

- Next.js（App Router）、TypeScript、Tailwind CSS、Drizzle ORMを入れる。
- 表の定義（docs/tech.md の4）を書く。Neonがまだなければ、手元ではSQLiteで動かせるようにしておく。
- 環境変数の一覧を `.env.example` に書く。`MOCK_EDITORS=1` のときAIを呼ばない仕組みを最初から入れる。
- 画面9つの空のページと、URLの割り当て（docs/wireframes.md の一覧）。
- 日本語フォント（Zen Kaku Gothic New、Rajdhani）を入れる。

終わりの確認: `npm run dev` で入口が開き、9つのURLがすべて表示される。

## 段階1 入口から結果まで（AIは呼ばない）

- 入口。お願いの4つ、残り回数、受付終了のときの切り替え。
- 端末の目印。最初に開いたときにクッキーで乱数を配る。
- 雑誌を選ぶ画面。3誌の名前、編集者、口ぐせ、見るところ、中身の会社名。休業中は灰色。
- 送る画面。ペンネーム、原稿、文字数、お題のボタン、見本で試すボタン。
- AIを呼ぶ前のチェック（lib/precheck.ts）。長さ、禁止語、同じ本文の2回目、同じ端末から1時間に5回、上限3000回。
- 読まれていく画面。単語ごとに分けて順に光らせる。編集者ごとの表示の文。
- 結果画面。引用、コメントを1文字ずつ、六角形の印、作品名、次のお願い、ほかの2人のひとこと、いまの掲載、投稿ボタン。
- `POST /api/submit` を、モック（docs/samples.md の結果を返す）でつなぐ。結果を保存し、`/r/{id}` で開ける。
- 見た目は mock/index.html から移す。空間の色、印の色、雑誌の色。

終わりの確認: スマホで入口から結果まで3分以内に通せる。同じ端末から6回目を送るとはじかれる。見本の結果に「見本」と出る。

## 段階2 表紙と目次

- 表紙の計算（lib/cover.ts）。雑誌ごとに、1人1作にまとめ、点数順に巻頭1、特集3、巻末6。あふれた作品と「名前だけ」は目次。発行後は固定。
- `GET /api/cover`。3誌の枠と目次を返す。本文もコメントも返さない。
- スマホの表紙画面。3誌を切り替え、その下に目次と「ペンネームで探す」。
- 大画面の表紙。3誌が並び、真ん中が大きい。10秒ごとに更新。新しく入った作品が光る。30秒ごとに真ん中を入れ替える。QRコード。
  最初はモックと同じCSSの3Dで作り、three.jsは段階8のあとに余裕があれば。
- 結果画面の「いまの掲載」を `GET /api/r/{id}/status` から取る。

終わりの確認: 結果を12件入れると、11件目で誰かが目次に下がる。発行すると表紙が変わらなくなる。

## 段階3 管理画面

- 合言葉で守る。
- 受付中と受付終了、上限回数、告知ツイートのURL、編集者ごとの出勤と休業、編集者ごとの厳しさ。
- 最近の結果の一覧と「表紙と目次から外す」。
- 「表紙を固める」（発行）。押すと published_at が入る。
- 今日の回数とエラー回数。

終わりの確認: 管理画面で受付終了にすると、入口が受付終了の画面になる。

## 段階4 指示文と定型文（キーなしで書ける）

- 3人に共通する土台の文（lib/editors/common.ts）。編集者であること、読者はAIであること、平易な日本語、引用の決まり、返す形。
- 3人それぞれの指示文（kurodo.ts、nina.ts、sol.ts）。性格、見るところ、話し方、癖4つ、作品の種類ごとの見るところ。
- 厳しさの一文（甘め、ふつう、厳しめ）と、割合を伝える一文の型。
- 改稿のときに前回を伝える文の型。
- 定型文（lib/lines.ts）。読んでいる間の表示、見なかった2人のひとこと（編集者×判定×作品の種類で5本ずつ、全部で約225本）。
- 有名作品の冒頭の一覧（lib/famous.ts）。50本ほど。空白と句読点を取り除いて先頭40字で照合する。当たったときの3人の決まった返事。
- 見本の原稿3本（lib/samples.ts）。
- 理由の札の一覧（10個ほど）。

終わりの確認: 指示文をあなたと一緒に読んで、docs/samples.md の例と食い違うところがない。

## 段階5 3社の接続

- 3社の呼び出し（lib/providers/）。決まった形で返させる。待ち時間の上限25秒。エラーは種類ごとに分ける。
- 返ってきたものの検算（lib/judge.ts）。引用が本文にあるか、判定が5つのどれか、点数が0から100か、作品名が15字以内か。
- 点数の計算と保存。
- 改稿。同じ端末から同じ雑誌への2回目以降を見つけ、前回を渡す。結果に「2稿目」と、点数が上がったか下がったか。
- 厳しさと割合。直近50件の判定の割合を数えて指示文に入れる。
- 今日の傾向（`GET /api/stats`）。理由の札の集計。入口と大画面に出す。
- 編集後記（lib/afterword.ts）。発行のときに3人ぶん作る。大画面と目次の下に出す。管理画面から書き直せる。
- 混んだときのやり直し。会社ごとに1分あたりの回数を数え、超えたら「前に何人かいます」と返し、スマホ側が数秒後にもう一度送る。

終わりの確認: 3社のキーを入れて、それぞれの編集者から本物の返事が返る。同じ端末から2回目を送ると前回の作品名に触れる。

## 段階6 結果の画像とXへの投稿

- `/r/{id}/opengraph-image`。雑誌の色の地に、六角形の印、作品名、作者名、雑誌名、編集者の顔。日本語フォントを同梱。
- 投稿ボタン。文の形は docs/tech.md の9。告知ツイートのURLは管理画面から。

終わりの確認: 結果のURLをXの投稿画面に貼ると、画像つきのカードが出る。

## 段階7 試して直す

- テスト用の原稿の束（docs/concept.md の12）を `scripts/judge-all.ts` で3人全員に見せ、結果を表にする。
- 判定の割合、引用の正しさ、コメントの平易さ、性格の出方を見て、指示文を直す。
- AIが書いた文章が載らないこと、有名作品がはじかれること、改稿が前回に触れること、を確かめる。
- スマホの実機で通しで確かめる。古めの機種でも動くか。

終わりの確認: 3人の性格の違いが、あなたが見て「わかる」と言える。

## 段階8 公開と当日の準備

- Vercelに置く。環境変数を入れる。Neonをつなぐ。
- 各社の管理画面で月の上限額を決める。
- QRコードを作り、ブースに貼る。
- 当日の朝の手順を書く。告知ツイートのURLを入れる、受付中にする、大画面を開く、動作を1回試す。
- 当日の終わりの手順を書く。受付終了にする、発行する、編集後記を確かめる、表紙を投稿する。
- 前日に通しのリハーサルをする。
